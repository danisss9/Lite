# Vendored AngleSharp.Css

This project builds the pinned upstream AngleSharp.Css library from source so the CSS 2.1
conformance track can carry parser patches the NuGet package does not have.

## Provenance

- Upstream: https://github.com/AngleSharp/AngleSharp.Css
- Base: tag `v1.0.2`, commit `d158478` (matches the NuGet package pinned in
  `Directory.Packages.props` at 1.0.2; verified by assembly identity: name `AngleSharp.Css`,
  version `1.0.2.0`, public key token `e83494dcdc6d31ea` from upstream's committed
  `Key.snk`, which this project signs with).
- Scope: `src/AngleSharp.Css/**` only (no upstream tests, benchmarks or docs). The upstream
  project file is replaced by `Lite.AngleSharp.Css.csproj`, which compiles the same sources
  for net6.0;net7.0;net8.0;net9.0;net10.0 against the vendored `Lite.AngleSharp` core instead of the NuGet AngleSharp.

## Patch policy

The `native/src` tree starts pristine. Every deviation from upstream MUST be listed here with
the CSS 2.1 suite evidence that motivates it, so the diff against the pinned tag stays
reviewable. Re-basing onto a newer upstream tag is a deliberate, separately-reviewed act.

| Patch | Motivation |
| --- | --- |
| 001 — CSS 2.1 §4.2 error recovery: `CssTokenizer.ContentFrom` reads a component-value run observing strings, comments and the matching pairs `()`/`[]`/`{}`, ends a declaration value at a top-level `;`/`}`, an at-rule prelude also at `{`, and a style-rule prelude only at `{`/`}`; a string broken by a newline (BAD_STRING) or a `url(` that is not a complete CSS 2.1 URI token (BAD_URI, which keeps its parenthesis open) invalidates the construct. `CssBuilder` drops such declarations and rules, skips malformed rule sets through their block, and skips declarations, statements and unknown at-rule preludes observing `()`/`[]`. `CssComponentScan.IsWellFormedValue` exposes the scan so Lite's raw `background` rescue rejects exactly what the parser rejects. | Upstream scanned raw text to the first `;`, `{` or `}` with no pair or BAD_STRING/BAD_URI handling, so it resynchronised at the wrong token: `@ import "x"; div {…}` kept the div rule (at-rule-001/011/012, at-rules-004), `url("x";` and `url(test/* test)` became background images (uri-003/012/013/016), and unknown at-rule preludes ended at a `;` inside `[ ]` (at-rule-013). Regression tests: `Lite.Tests/CssErrorRecoveryTests.cs` (all five fail against the pristine source). |
| 002 — `ColorParser.ParseRgbComponent` clamps a percentage component to 0..255 before the byte conversion. | §4.3.6 requires out-of-gamut values to be clipped, but the unclamped `(Byte)` cast wrapped `rgb(101%, …)` (257.55) to 2 (outline-color-057, background-color-057 family). Rounding stays upstream's: CSS 2.1 leaves it undefined and the suite encodes both choices (colors-001 needs 50% = #80, background-color-052's swatch is #7f), so the harness compares "same color" swatches within one level. Regression test: `Lite.Tests/CssErrorRecoveryTests.cs` `PercentageRgb_ClampsToTheGamut`. |
| 003 — `StyleCollectionExtensions.ComputeExplicitStyle` cascades the `style` attribute of any element in the XHTML or SVG namespace, not only `IHtmlElement`/`ISvgElement` instances. | A document served as `application/xhtml+xml` is parsed by AngleSharp.Xml into generic elements, so every inline declaration except Lite's own font-size lookup was dropped: ~250 `table-anonymous-objects` reftests (and every other `.xht` case using `style=""`) drew uncoloured, unpositioned content. Regression test: `Lite.Tests/XhtmlTests.cs` `XhtmlInlineStyleAttribute_Cascades` (fails against the pristine source). |
| 004 — §6.4.1 cascade origins: new `Dom/CascadeOrigin.cs` lets the host mark the style elements carrying its user-agent and user sheets; `SortBySpecificity` orders matches by origin (default sheet < user agent < user < author) before specificity, and `ComputeExplicitStyle` re-applies user `!important` declarations last. `CascadeOrigin.Of` is public, so the host orders the rules it applies through its own channel (dynamic pseudo-classes, `:link`) in the same cascade. | Upstream sorted every match by specificity alone, so the default sheet and Lite's injected UA sheet competed with author rules: `body { margin: 8px }` beat an author `* { margin: 1em }` (background-root-*), and the default sheet's `form`/`ul` margins leaked the same way. Regression tests: `Lite.Tests/CascadeOriginTests.cs`, `StyleSheetControlsTests.UserStyleSheet_LosesToAuthorNormalAndBeatsAuthorImportant`. |
| 005 — `display: flow-root` is a known keyword (`DisplayMode.FlowRoot`, `CssKeywords.FlowRoot`, the display map). | Upstream 1.0.2 dropped the declaration as invalid, so a flow-root box computed to `block` and never established a block formatting context: it overlapped preceding floats (floats-wrap-bfc-with-margin-001, a curated test that had passed only because its script-built reference was equally unstyled). Regression test: `Lite.Tests/DynamicStyleTests.cs` `FlowRoot_EstablishesABfcBesideAFloat`. |
| 007 — `CssListValue<T>.Compute` keeps an absent list item absent instead of computing it. | A multi-layer `background` shorthand whose later layer omits a component (`url(x) 0 0 / 50px 100px no-repeat, red`: the `red` layer has no size) stores a null in that longhand's list, and computing the list dereferenced it — a `NullReferenceException` that aborted the element's whole computed style (line-height-201 crashed the render). Regression test: `Lite.Tests/DynamicStyleTests.cs` `LayeredBackground_WithAnOmittedComponent_Computes`. |
| 006 — `MediaListExtensions.Validate` compares media types case-insensitively (`KnownTypes` lookup with `StringComparer.OrdinalIgnoreCase`, and `Isi` for the device-category match). | CSS 2.1 §7.3 makes media type names case-insensitive, but upstream matched them ordinally, so `<style media="Screen">` read as an unknown type and its whole sheet was dropped on screen (Lite's own `@media` evaluator was already case-insensitive). Regression test: `Lite.Tests/Css21ObligationTests.cs` `MediaTypes_AreRecognizedCaseInsensitivelyAndOthersIgnored` (fails against the pristine source). |
| 008 — Escaped newlines in strings: `CssTokenizer`'s string and quoted-URL states and the micro `StringParser`/`CssUriParser` remove a backslash-escaped newline instead of appending `Environment.NewLine`. | CSS 2.1 §4.3.7 / §4.1.3: "The newline is subsequently removed from the string." Upstream inserted CR LF on Windows, so `content: "Th\<newline>is "` generated "Th", a line break and "is " (escapes-000, escaped-newline-001). Regression test: `Lite.Tests/CssErrorRecoveryTests.cs` `EscapedNewlineInString_IsRemoved` (fails against the pristine source). |
| 009 — End of style sheet closes open constructs: `CssTokenizer.ContentFrom` appends the closers of every still-open `()`/`[]`/`{}`, a string open at the end is closed, and a `url(` open at the end is a complete URI token. A standalone `CssComponentScan.IsWellFormedValue` still rejects an unclosed value (its returned text grows). | CSS 2.1 §4.2 "Unexpected end of style sheet": user agents must close all open constructs at the end of the style sheet. Upstream kept `rgb(0, 128, 0` unclosed, which no converter accepts, and read an unclosed `url(` as a BAD_URI (eof-002, uri-017). Regression test: `Lite.Tests/CssErrorRecoveryTests.cs` `EndOfSheet_ClosesOpenConstructs` (fails against the pristine source). |
| 010 — CSS 2.1 selector validation & ASCII case-insensitive pseudo names in `CssBuilder.CreateStyle`: rejects empty comma-separated selector items (`body,,div`), tokens after a pseudo-element (`p:first-line[id="p1"]`, `p:first-line+p`, `p:first-line.two`), and class/ID identifiers starting with an unescaped digit or `-`+digit (`.-1ident`, `#-1ident`); ASCII-lowercases pseudo-class and pseudo-element names outside strings/`[]`/`()`. | CSS 2.1 §4.1.3, §4.1.7, §5.2.1, §5.10, §5.12: upstream accepted `body,,div`, accepted selectors with tokens after a pseudo-element, accepted `.-1ident`/`#-1ident`, and matched pseudo-class/pseudo-element names case-sensitively (bad-selector-001, pseudo-007, pseudo-008, pseudo-014, pseudo-016, c25-pseudo-elmnt-000, ident-003). Regression test: `Lite.Tests/CssErrorRecoveryTests.cs` `SelectorValidation_EnforcesCss21GrammarAndCaseInsensitivePseudos` (fails against the pristine source). |
| 011 — CSS 2.1 color syntax in `ColorParser`: `Literal` accepts only 3-digit and 6-digit hex colors (rejecting 4-digit `#1000` and 8-digit hex), and `ParseRgbaLegacy` rejects mixed percentage and integer components (`rgb(100%, 0, 0)`). | CSS 2.1 §4.3.6 defines `#rgb`, `#rrggbb`, and `rgb()` with either three integers or three percentages (never mixed). Upstream accepted `#1000` as CSS Color 4 RGBA and accepted `rgb(100%, 0, 0)` (color-030, outline-color-030, colors-004). Regression test: `Lite.Tests/CssErrorRecoveryTests.cs` `ColorSyntax_RejectsFourDigitHexAndMixedRgbUnits` (fails against the pristine source). |
| 012 — Declaration property-name validation & recovery + escaped newlines in selector strings in `CssBuilder`: `CreateDeclarationWith` requires an `Ident` property name (rejecting quoted `'color': red;`), does not enter CSS nesting on a leading `:` (`:red; color:green;`), and `TryNormalizeAndValidateSelector` removes backslash-escaped newlines inside selector strings. | CSS 2.1 §4.1.1, §4.2, §4.3.7: upstream accepted `'color': red;` as `color: red`, let CSS nesting consume `:red; color:green;` through `}`, and kept `\`+newline inside selector strings (quoted-keywords-001, malformed-decl-008, strings-000). Regression test: `Lite.Tests/CssErrorRecoveryTests.cs` `DeclarationPropertyValidationAndSelectorEscapedNewline` (fails against the pristine source). |
| 013 — `CssBuilder.CreateValue` recognises a declaration priority as `!` followed by optional whitespace and `important` (and trailing whitespace), instead of requiring the exact string `!important`. | CSS 2.1 §4.1.9: "a declaration's priority is `!` followed by optional white space and the keyword `important`". Upstream dropped the priority of `! important`, so `@import "support/cascade-012.css"` (`.test { color: green ! important }`) cascaded as a normal declaration and the later `color: red` won (cascade-012). Regression test: `Lite.Tests/CssErrorRecoveryTests.cs` `BangImportant_AllowsWhitespaceBeforeTheKeyword` (fails against the pristine source). |

## Coordination

The HTML track's AngleSharp core fork (`Lite.AngleSharp`) is the dependency; AngleSharp.Xml
stays on its NuGet pin and binds the vendored core by its unchanged strong-name identity.
Changes here must keep `--suite css21`, `--suite html5` and `--suite wpt` green.
